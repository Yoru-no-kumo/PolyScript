# PolyScript AI — 데이터 정책

버전 0.3 · 한국어 · 검토본 · 2026-10-19 (Asia/Tokyo)

## 1. 적용 범위

개인용 Windows 앱의 미디어·분석 결과·사용자 수정·화자 자료·출력을 다룬다. [기존 승인 Foundation](../old/foundation/project_foundation.v0.2.ko.md) §12·16·17의 신뢰·목적·수명주기 원칙을 유지한다. 세부 저장·삭제 기능의 구현 완료나 법률적 허용 여부를 새로 선언하지 않는다.

## 2. 데이터 종류

| 종류 | 유지할 책임 | 미결사항 |
| --- | --- | --- |
| 입력 미디어 | 분석·재생의 근거, 출처 추적 | 복사/참조·원본 변경 감지·저장 위치 |
| 파생 오디오·분석 결과 | 검수·재현·처리 재사용 | 형식·보존 단위·기간 |
| 공식 원문·번역·시간축 | 현재 채택한 학습·출력 데이터 | 저장 엔진·채택 단위 |
| 사용자 수정·검수 이력 | AI 결과와 구분, 무조건 덮어쓰기 금지 | 이력 깊이·복구·병합 UI |
| 화자 프로필·샘플 | 프로젝트 간 재사용과 근거 보존 | 라이브러리·선정·삭제 연동 |
| Script·Subtitle 출력 | 앱 밖에서 활용하는 독립 산출물 | 형식별 옵션·출력 이력 |
| 캐시·임시 파일 | 성능 보조, 유일한 공식 데이터로 사용하지 않음 | 정리 시점·용량·재생성 비용 |
| 엔진·모델 파일 | 처리 환경의 재현 근거 | 다운로드·설치·버전 보존 |
| 진단·변경 기록 | 진단 로그와 검수 근거를 구분 | 민감정보·기간·외부 전송 |
| Dataset·학습 모델 | 고급 학습 채택 시 조건부 관리 | 구조·삭제 영향·적용·복귀 |

메타데이터와 대용량 파일의 책임 분리는 유지한다. PostgreSQL·SQLite·파일 기반 저장 등은 미선정이다.

## 3. 공식 상태·신뢰·허용 목적 — 유지

`AI 후보 ≠ 공식 채택 데이터 ≠ 신뢰 조건을 통과한 데이터`

`신뢰된 데이터 ≠ 학습 가능한 데이터 ≠ 배포 가능한 데이터`

사용자 확인·분석 신뢰도·허용 용도는 서로 다른 정보다. 높은 품질이나 개인 보유 사실만으로 모든 목적을 허용하지 않는다.

## 4. 목적별 사용 범위 — 기존 구분 유지

| 목적 | 의미와 현재 경계 |
| --- | --- |
| Processing | 요청한 분석·결과 생성. 저장·학습 허용을 자동 포함하지 않음 |
| Storage | 원본·파생 자료 저장·보존. 기간과 백업 범위는 미결 |
| Quality Improvement | 품질 분석·통계·최적화. 모델 학습을 자동 허용하지 않음 |
| Global Knowledge | 과거의 프로젝트 범위를 넘는 지식 활용 분류. 개인 라이브러리와의 범위 매핑은 미결. 외부 사용자 공유는 현재 범위 밖 |
| Training | Dataset 구성·모델 학습. 별도 적격성·목적 확인 필요 |
| Distribution | 외부 배포·공유. Export 기능과 실제 배포 허용 여부는 구분 |

이는 개념 구분이며 여섯 Boolean 필드를 만들라는 스키마 지시가 아니다. 개인용 권한 선언·확인 UX, 적용 범위·기간·철회 방법은 미결이다.

권리·사용 범위가 불명확한 자료는 Restricted를 기본으로 다룬다. 이는 포괄 허가나 단일 전면 금지 판정이 아니라 해당 목적의 허용 범위를 확인해야 한다는 뜻이다. 개인용·로컬 사용만으로 제한을 해제하지 않는다.

## 5. 출처·버전·사용자 수정 — 유지

입력·엔진·모델·설정·검수 이력을 산출물과 연결한다. 개인 화자 샘플에도 프로젝트·구간·확인 근거를 남긴다. 재분석 결과는 현재 채택본과 구분하며 사용자 수정의 무조건 덮어쓰기를 금지한다.

원문·시간축·화자 수정이 영향을 주는 번역·자막·지식을 식별한다. 충돌 처리와 이력 저장 방식은 미결이다.

## 6. 보존과 삭제 — 기존 원칙 유지

보존은 시간·가치·허용 목적·의존관계를 함께 고려한다. 프로젝트 종료만으로 모든 근거에 같은 TTL을 적용하지 않는다.

`생성 → 사용 → 보관 / 보존`

`삭제 요청·판단 → 논리 삭제 → 복구·보존 구간 → 정책·의존성 확인 → 물리 삭제 / 익명화`

이는 개념적 정책이다. 구현 완료나 복구 구간의 무조건 보존 허가를 뜻하지 않는다. LONG_TERM/PERMANENT는 허용된 가치 있는 근거의 장기 보존 분류다. PERMANENT는 자동 만료가 없다는 뜻이며 삭제 불가를 뜻하지 않는다.

품질·신뢰도·현재 활용성·희소성·대체 가능성·출처 완전성·역사적 가치를 평가한다. 점수·가중치·주기·자동 정리 기준은 미결이다.

프로젝트 삭제 시 다음을 구분해야 한다.

- 사용자가 보유하던 원본과 앱이 복사해 관리하는 파일
- 프로젝트 전용 산출물과 다른 프로젝트에서도 사용하는 화자 샘플
- 앱 내부 데이터와 이미 내보낸 파일
- 운영 데이터와 백업·복제본
- 학습 원천과 이미 생성된 Dataset·모델

**제안:** 삭제 전 대상·공유 참조·영향을 사용자에게 보여준다. 원본 삭제 기본값·연쇄 삭제·복구 기간·백업 반영·익명화·모델 재학습 및 unlearning 보장은 미결이다. 의존관계만으로 불허 자료를 무기한 보존하지 않는다.

## 7. 외부 전송·자격증명

외부 API·원격 처리·동기화·진단 전송은 아직 채택되지 않았다. 도입 시 데이터·목적·수신처·보관 조건·실패 동작을 정하는 방향을 제안한다. 음성·화자 샘플·전사·번역의 실제 전송 범위를 따로 검토한다.

API 키 보관, 로그 민감정보 제거, 파일 암호화, Windows 계정 간 접근 방식은 미결이다. 기존 보호 수단의 제안 상태를 확정으로 올리지 않는다.

## 8. 백업과 복원

백업·복원 체계를 갖추는 기존 방향을 유지한다. 메타데이터만 복사하고 미디어·화자 근거·산출물 참조가 끊긴 상태를 완전 복원으로 취급하지 않는다.

**제안:** 백업 일관성, 원본 포함 여부, 모델·캐시의 재확보, 복원 후 경로 재연결을 함께 설계한다. 위치·주기·암호화·세대 수·복구 시간·손실 허용량은 미결이다. 현재 백업 기능이 존재한다고 가정하지 않는다.

## 9. 우선 결정할 사항 — 제안

원본 복사/참조, 개인 라이브러리의 프로젝트 독립성, 외부 전송 범위, 삭제·복구 기본값과 백업 묶음을 먼저 결정하고 저장 스키마와 화면 동작을 구체화한다.
