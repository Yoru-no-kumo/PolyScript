# 문서 작업 지침

## 적용 범위

이 파일은 docs 전체와 모든 하위 폴더의 문서 작업에 적용한다. 사용자 지시를 우선한다. 기존 docs/00_foundation/AGENTS.md의 문서 관리 원칙을 현재 폴더 구조에 맞게 이곳으로 이전했다.

## 구성과 이름

- docs/README.md를 문서 진입점으로 유지한다.
- 현재 문서는 foundation, decisions, architecture, data, history처럼 목적별 폴더에 둔다.
- 설계 문서명은 `<주제>.v<버전>.ko.md` 형식을 사용한다. README.md와 AGENTS.md에는 설계 버전을 붙이지 않는다.
- 같은 목적·버전·언어의 문서는 대표본 하나만 유지한다. 승인본을 검토본보다 우선한다. 내용 차이를 확인하고 고유한 결정·근거가 있으면 대표본 또는 변경 기록에 보존한 뒤 중복본을 제거한다.
- 다른 목적의 문서(예: Foundation, Inventory, ADR, 변경 검토서)를 요약 내용이 겹친다는 이유만으로 삭제하지 않는다.
- 이전 버전은 docs/old/<목적>/에 보관한다. 현재 버전이나 다른 목적의 최신 자료를 이전 버전과 함께 일괄 이동하지 않는다. 사용자 지시로 과거 기준 자료를 보관할 때는 상태와 이유를 기록한다.

## 상태와 검증

- 새 버전 작성·정식 승격은 사용자 지시의 상태와 범위를 따른다. 문서 승인과 개별 확정·미결·제안·실험 상태를 구분한다.
- 새 버전의 내용과 저장 결과를 검증한 뒤 이전 활성 버전과 중복 백업을 정리한다.
- 이동·삭제 전 절대경로가 의도한 docs 범위 안인지 확인한다. 기존 보관 파일을 덮어쓰지 않는다.
- 기존 내용·파일명 보존을 원칙으로 하되 사용자가 명명 정리를 요청한 경우 새 이름과 대응 관계를 변경 기록에 남긴다. 경로 변경에 따른 링크는 갱신한다.
- 문서 링크, README 진입점, 버전·언어·문서 상태와 중복 여부를 검증한다.
- synced sources 자료는 이동·수정·삭제하지 않는다.

## 검토 자료

정식 문서 반영 완료 후 필요한 결정 근거·미결사항·변경 내용을 보존하고 저장 결과를 검증한 뒤 해당 작업의 리뷰노트를 삭제하는 기존 정책을 유지한다. 새 검토본 작성만으로 정식 승인이나 리뷰노트 삭제 조건을 충족했다고 해석하지 않는다. 보관된 과거 검토서는 중복 본문과 구분하며 고유한 근거를 보존·이관했는지 확인한다.
